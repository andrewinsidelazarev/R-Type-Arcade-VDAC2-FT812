# Демо нового транслятора — 12 сентября 2026

Ниже — состояние сохранённой v006 и оставленного пользователю запуска.
Дальнейший backend разрабатывается отдельно: см. `TRANSLATOR_STAGE_BACKEND.md`.
Рабочая проверочная SPG с исполняемым скроллером лежит в `Build/TranslatorGame`,
а не по пути запущенной v006. Сборщик теперь подключает скроллер при новой сборке.

v005: пользователь подтвердил «В общем, работает. И это круто!».
v006: пользователь подтвердил темп текущего запуска — «как в оригинале».
Это наблюдение пользователя, не утверждение об аппаратно доказанных 55 кадрах/с.

Запуск: корневой `run_translator_demo.cmd`.
SPG: `Build/TranslatorDemo/rtype_vdac2.spg`.
Сборщик: `Source/Tools/build_translator_demo.py`.
C: `Source/C/demo/`.

Это ограниченный профиль AST → C → SDCC, не завершённый перенос всей объектной
игры и не демонстрация готовности полной PZVT VM. Старая игровая ASM-часть не
подключается. ASM обслуживает только загрузку, ввод, FT812 и начальные IRQ.

Подключены движение и наклон R-9, запросы обычных выстрелов, заряд и индикатор
Beam, Wave Cannon (выпуск, задержка, пять мощностей, движение и анимация),
красные враги с исполнением ScriptedMotion.update, счётчики кадра и
дистанции. Графика берётся из готовых HQ-ресурсов активного Python.
Меню, ландшафт, коллизии, смерть, Force/Bits и звук не подключены.
1100 тактов образуют повторяющийся демонстрационный сценарий, не полный уровень.
Показатель LIVES 8 взят из INITIAL_LIVES; жизненный цикл в демо не исполняется.

## Исправленные остановки

- На старте FT_DELAY исполнял HALT после DI. Теперь на время инициализации FT812
  включаются кадровые IM2-прерывания; затем основной цикл ждёт swap FT812.
- На такте 1014 срабатывала ошибка 4: восемь статических записей врагов были
  недостаточны. В сценарии Python одновременно живут до 12 красных врагов.
  Сборщик задаёт безопасную верхнюю границу 22 по числу событий рождения.
- Формат битмапа FT812 исправлен с L8 (3) на ARGB4444 (6).

## Изменения v006

- Wave.init, __post_init__, обновление, выпуск и выбор изображения генерируются
  из соответствующих AST-блоков Game/Wave. Провайдер пустой сцены возвращает
  нулевой урон: взаимодействие Wave с противниками пока не реализовано.
- Универсальный модуль finite_expression.py табулирует чистое целочисленное
  выражение по конечному аргументу. В этой сборке 66 656 значений: полный u16-домен
  координаты пули и логические координаты игрока. Таблицы занимают 266 624 байта
  основной RAM, не RAM_G. Это таблицы выражений, не записанные траектории врагов.
  Доказательства доменов пока задаёт профиль, общего вывода диапазонов записей нет.
- Деление вниз на положительную степень двойки генератор заменяет ASR i32;
  отрицательные значения проверены исполнением скомпилированного Z80-кода.
- Для красных спрайтов смещение дескриптора помещено внутрь round. Координаты
  и индекс кадра выбираются таблицами, без длинного деления при каждом blit.
- Контроль строк использует разности и битовую маску занятых физических строк.
  Каждая из 768 строк учитывается отдельно; пустые группы лишь пропускаются.
- Сборщик отвергает пересечение _CODE/_HOME, выход данных в область стека,
  неинициализированные CRT-секции и пересечение физических страниц ресурсов.

Исходники активной Python-игры не изменялись. v005 сохранена отдельно и не
перезаписывалась. Текущая v006: RAM_G 398 840 байт, кодовая секция и служебные
секции проверяются по linker map до упаковки SPG.

## Проверки

`check_translator_demo.py` отвергает DI/HALT, моделирует вход в IM2 при разрешённом
кадровом IRQ, проверяет загрузку RAM_G, последовательность кадров, стек и формат
ARGB4444. Полный универсальный симулятор этим не заменяется.

`test_translator_demo.py`: четыре теста, включая 2000 случайных наборов точных
строчных интервалов, полный u16-домен таблицы и отрицательные проверки раскладки.
Сборщик также исполняет 65 975 исчерпывающих проверок скалярных функций.

`check_translator_demo_parallel.py --workers 4 --frames 1108`: все 1100 кадров
сценария и восемь после его повторного запуска. В каждом процессе логика Z80
идёт непрерывно; между процессами делится только независимая подготовка вывода.
Проверены состояние R-9, пули, все пять мощностей Wave, красные враги против
M72EnemyWorld.update, координаты вывода красных врагов/Wave и невмешательство
Render в игровое состояние. Это проверка поддержанного профиля, не всего Game.

Результат v006: 1108 кадров без расхождений; максимум строковой оценки 1190 при
лимите 1209, наблюдаемое использование стека до 84 байт. Полный начальный кадр
в модели: 147–156 тысяч тактов против 400–471 тысячи в v005. В плотном сценарии
максимум Tick+Render 300 006 тактов, без платформенного ввода, SPI и ожидания swap.
Поэтому устойчивые 55 кадров/с для любой сцены аппаратно пока не гарантируются;
не следует менять игровые скорости ради подгонки этого замера.

Патченный Unreal проверяется через dump.req; файл `native_check.json` относится
только к указанному в нём SHA-256 SPG. Нельзя выдавать результаты старого запуска
за проверку новой сборки. Активный пользовательский запуск без запроса не менять.

В проверке v006 пользователь сам управлял запущенной игрой; одновременно тест
подавал ЛКМ. Этот сеанс нельзя считать изолированным тестом ввода. Тест завершён,
vmouse.bin отключён (active=0); экземпляр Unreal оставлен пользователю. Во время
сеанса дампы показывали продвижение сцены, повтор цикла, целый защитный байт стека
и отсутствие кода ошибки. Подтверждение темпа принадлежит пользователю.
