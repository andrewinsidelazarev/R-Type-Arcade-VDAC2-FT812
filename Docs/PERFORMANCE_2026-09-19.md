## Изменение

В загрузчиках `Source/ASM/rtype_boot.asm` и `v30z80_boot.asm` разрешён кэш
окна W3 (`#C000…#FFFF`): CacheConfig = `#0F` вместо `#07`.
В W3 выполняются переведённые банки, видеоадаптер, звуковой адаптер и банки p2c.
Раньше каждое чтение этого окна было промахом независимо от содержимого кэша.

Основание: [документация TS-Conf](https://github.com/tslabs/zx-evo/blob/master/pentevo/docs/TSconf/tsconf_en.md)
и реализация тегов/записей в `z80_main.inl` установленного исходника Unreal
(`E:/zx/unreal-tsfm/zx-evo/pentevo/unreal/Unreal`). Тег содержит физическую страницу;
переключение PAGE3 само по себе не даёт устаревшего чтения. DMA обходит кэш,
поэтому отдельно проверены совпадения кэшированных данных с RAM после DMA.

В `rtype_boot.bin` изменился один байт по смещению 670: `07 → 0F`.
В упакованной SPG изменились этот байт по смещению 1694 и четыре байта времени/даты
упаковки в заголовке (45, 60…62). Все 206 файлов страниц машины побайтово прежние.
Логика, ввод, координаты, порядок отрисовки, ресурсы и звуковые команды не правились.
Частота CPU и видеорежим тоже прежние; число команд FT812 и нагрузка на строку не растут.

## Проверки и измерения

`rtype_check.py` сравнил с CPython 9000 кадров с неуязвимостью/автоогнём
и 2400 кадров со случайным вводом (seed 31): память машины, буфер спрайтов,
вызовы платформы, состояние музыки и последовательность записей TSFM совпали.
Неуязвимость — только параметр проверочного сценария, в SPG не добавлена.
Эти проверки исполняют страницы программы после загрузчика и сами по себе
не проверяют аппаратный кэш: для него добавлен отдельный пассивный аудит.

| Выборка аудита | Чтений CPU | Промахов при #07 | Промахов при #0F | Устаревших чтений при #0F |
|---|---:|---:|---:|---:|
| Запуск и переход в игру, 1…420 | 39 503 526 | 17 858 834 | 10 334 519 | 0 |
| Автоогонь, 1200…1299 | 12 831 384 | 8 636 271 | 3 526 717 | 0 |
| Случайный ввод, 1600…1699 | 11 081 530 | 7 339 885 | 3 061 508 | 0 |
| Поздний участок, 8800…8899 | 11 423 522 | 7 696 253 | 3 109 782 | 0 |

На участке 1200…1299 промахов меньше на 59,2%. Это **не прирост FPS на 59,2%**.
Аудит воспроизводит теги/заполнение/инвалидацию кэша Unreal, но не такты арбитража
DRAM, задержки DMA, SPI и развёртки FT812. Реальный FPS в Unreal ещё не замерен;
устранение всего двукратного отставания этой правкой не подтверждено.

Пассивный аудит возвращает CPU текущие байты RAM, не вмешиваясь в проверяемую игру,
и отдельно обнаруживает чтения, которые дали бы устаревшие данные при каждой маске.
Пять unit-тестов проверяют заполнение пары байтов, физические теги, алиасы окон,
инвалидацию CPU-записью, обнаружение DMA-изменения и работу callback реального ядра Z80.
На кадрах 1…420 и 1200…1300 дополнительно совпали хеши display list + RAM_G с базовой сборкой.

Профиль плотного участка 900…3000 без ожиданий оборудования: BulletBatch 9,1%,
Sprite1 6,4%, SpritesBuild 5,2%, SpriteEntry 3,8%, BoxTest 2,6%.
Медиана полного кадра при выводе каждого кадра — около 536 тыс. номинальных тактов.
Следующая оптимизация должна уменьшать стоимость этих операций с сохранением
покадрового состояния, а не менять скорость объектов или ввод.

## Воспроизведение

Из корня проекта, с `PYTHONPATH=Source/Tools;Source/Python;Build/PythonDeps`:

```text
python -m unittest Source.Tools.test_tsconf_cache_probe -v
python Source/Tools/rtype_check.py --frames 3000 --render "" --invincible --autofire 400 --profile 997 --profile-from 900 --ticks Build/profile.json
python Source/Tools/rtype_check.py --frames 1300 --render "" --invincible --autofire 400 --cache-probe 1200:1299 --ticks Build/cache-probe.json
python Source/Tools/rtype_spg.py --skip-parts --output Build/SpeedOptimization/2026-09-19/cache-all/rtype_vdac2.spg
```

Для проверок без окна/аудиовывода: `SDL_VIDEODRIVER=dummy`, `SDL_AUDIODRIVER=dummy`.
В отчётах проверок «к/с» — скорость работы проверки на ПК, не FPS целевой игры.
`--output` сохраняет отдельную SPG; загрузчик и промежуточные файлы упаковки
пересобираются в обычном Build. Сам этот вызов не заменяет `Build/V30Z80/rtype_vdac2.spg`;
после проверки кандидат отдельно скопирован туда и в комплект `Build/_SD/R-Type VDAC2`.
