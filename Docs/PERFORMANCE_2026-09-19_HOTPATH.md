# Оптимизация Z80: спрайты, пачка пуль, CMP/TEST — 19 сентября 2026

Работа выполнена без агентов. Актуальный комплект для реальной машины:
`Build/_SD/R-Type VDAC2/rtype_vdac2.spg` и `RTYPELVL.PAC`.
Пак ресурсов, игровая логика, управление, частоты CPU/видео и `SKIP_MAX = 1` не менялись.
Предыдущее разрешение кэша W3 (`CacheConfig = #0F`) сохранено.

## Что изменено

1. `Source/ASM/v30z80_host.asm`: `Sprite1` и `SpriteCell` пишут готовые байты вершины
   из регистров напрямую через HL. Убраны промежуточный `SE_B1` и повторное чтение байта
   между проходами A/B. В `SpritesBuild` счётчик записей хранится в B; BC сохраняется
   на время `SpriteEntry`. Список адресов спрайтов остаётся на стеке в прежнем порядке.
   При просмотре байтов 7…5 записи используются `DEC L`: запись выровнена по 8 байтам,
   поэтому эти два уменьшения не пересекают границу 256 байт. Объём кода/данных хоста
   до таблиц уменьшился на 31 байт (`HOST_END #F32F → #F310`).
2. `Source/ASM/v30z80_kernels.asm`, `BulletBatch`: проверка `[2EFC] < #3F00` перенесена
   на вход пачки. После неё ядро может записывать туда только значение `< #3C8`;
   движение `[bp+3…5]` при BP, кратном 16, не затрагивает `[2EFC…2EFD]`.
   Удалена промежуточная запись AX, гарантированно заменяемая до любого выхода.
   Сравнения X с #140/#2C0 выполняются со старшего байта вместо вычитания полного слова.
   Ни границы, ни условия уничтожения пуль не изменены.
3. `Source/Tools/v30z80/codegen.py`, `quick_zero_test16`: универсальное сокращение
   CMP слова с 0/FFFF и TEST с однобайтовой маской. Условия применения: непосредственный
   операнд, слитая цепочка только JE/JNE, все флаги на её выходах мертвы по анализу живости.
   В других случаях остаётся общий шаблон. CMP 0 заменяется OR двух байтов; CMP FFFF —
   AND двух байтов и INC; TEST — AND выбранного байта. Регистры V30 не записываются.
   Операнд памяти по-прежнему читается полным словом через существующий адаптер,
   включая обработку границы страницы и даже нулевую маску.

Команды FT812, порядок слоёв и содержимое RAM_G не изменились: это подтверждено хешами
каждого кадра. Дополнительной нагрузки на строку FT812 нет.

## Проверки

- Финальная сборка: 12000 кадров с автоогнём/неуязвимостью и 4000 со случайным вводом
  seed 31. Память V30, буфер спрайтов, вызовы платформы, команды и состояние TSFM
  совпадают с эталоном. Display list и RAM_G совпадают с прежней сборкой на каждом кадре.
- `v30z80_check`: 4000 кадров seed 31, дополнительно совпадают регистры V30, FLAGS,
  IP, PIC и регистры видео.
- `v30z80_sprite_check`: 23056 отдельных записей и 1000 полных пачек. Границы экрана,
  формы 1…8 ячеек, отражения, оба прохода, смена палитры, пустой хвост, 128 видимых
  записей, порог переполнения. Вывод, отметки использования слотов, состояние рендера
  и возврат стека совпадают. Экономия всей синтетической выборки — 1,381%.
- `v30z80_bullet_check`: 10000 случаев — переполнения/заёмы координат, обе границы,
  ёмкость буфера, короткие/длинные пачки, отказы и выход к уничтожению.
  Совпадают виртуальные регистры, память и вид выхода. Экономия выборки — 4,999%.
- `test_v30z80_zero_test`: 4 теста; на ядре Z80 перебраны все 65536 значений для
  9 шаблонов (589824 исполнения), проверены ZF и сохранность исходного слова.
  Проверены запреты оптимизации при живых флагах/других условиях/внешнем входе,
  сохранение полного чтения операнда памяти.
- Пассивный аудит кэша, кадры 1200…1299: 12654129 чтений, 3445778 промахов при #0F,
  устаревших чтений 0. Этот аудит проверяет согласованность данных, не аппаратный FPS.

## Воспроизведение

Из корня проекта; `PYTHONPATH=Source/Tools;Source/Python;Build/PythonDeps`,
`SDL_VIDEODRIVER=dummy`, `SDL_AUDIODRIVER=dummy`:

```text
python -m unittest Source.Tools.test_v30z80_zero_test -v
python Source/Tools/v30z80_sprite_check.py --before Build/SpeedOptimization/2026-09-19/baseline/V30Z80
python Source/Tools/v30z80_bullet_check.py --before Build/SpeedOptimization/2026-09-19/baseline/V30Z80
python Source/Tools/v30z80_check.py --frames 4000 --seed 31
python Source/Tools/rtype_check.py --frames 12000 --render "" --invincible --autofire 400 --dl-compare Build/SpeedOptimization/2026-09-19/sprite-hotpath/before-dl.json
python Source/Tools/rtype_check.py --frames 4000 --render "" --random 31 --dl-compare Build/SpeedOptimization/2026-09-19/sprite-hotpath/before-random-dl.json
```

JSON замеров: `Build/SpeedOptimization/2026-09-19/sprite-hotpath`:
`before.json`, `after-codegen.json`, `before-random.json`, `after-codegen-random.json`,
`registers-codegen.json`, `cache-codegen.json`. Промежуточные `after.json` и
`after-vertices.json` относятся к предыдущим шагам этой же оптимизации, не к финалу.
