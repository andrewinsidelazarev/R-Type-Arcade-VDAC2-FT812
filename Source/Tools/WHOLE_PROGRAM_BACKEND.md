# Быстрый цикл разработки транслятора

## Исправление подхода — 2026-09-05

Уменьшение числа неразобранных вызовов и успешная компиляция C не доказывают
исправность или ускорение игры. Новый whole-program runtime ещё не включён
в игровой SPG. Повторная сборка старого SPG не проверяет этот runtime.
Показатели backend, проверки семантики и состояние готовой игры должны
учитываться раздельно.

Вместо полного повторного разбора проекта после каждой правки backend:

```powershell
python Source/Tools/rebuild_whole_program_backend.py
python Source/Tools/rebuild_whole_program_backend.py --check
python Source/Tools/rebuild_whole_program_backend.py --refresh-frontend
```

Первая команда проверяет сохранённые frontend IR против текущих исходников,
пересчитывает вызовы, генерирует PZVT, проверяет Z80 ABI/стек и согласованность
пакета. Результат изолирован в `Build/WholeProgramBackend`; игровой SPG,
исходный Python и результаты последней полной трансляции не заменяются.
Устаревший frontend IR отклоняется: в этом случае необходима полная генерация.

Повторное использование допускается только при совпадении SHA-256 всех
учтённых входов, компилятора, runtime и каждого обязательного файла результата.
Изменение файлов во время сборки вызывает отказ и восстановление предыдущего
пакета. `backend_build.json` содержит фактическое время и оставшиеся препятствия
для исполнения. `--check` ничего не генерирует и возвращает ошибку для
устаревшего/изменённого пакета. `--force` принудительно повторяет генерацию.

`--refresh-frontend` заново строит IR из текущих исходников в
`Build/WholeProgramFrontend`, не обновляя подпись старого IR и не запуская
конвертацию графики. Следующие сборки используют этот изолированный frontend.
Время обновления frontend учитывается отдельно и входит в общее время сборки.

## Изменения семантики и вычислений

- Анализ доступных SSA-определений общий для анализа вызовов и генерации.
  Доминирование вычисляется один раз на CFG с битовыми множествами.
  Неоднозначные определения, определения только из другой ветви или обратного
  ребра цикла не принимаются за единственное доказанное значение.
- Прямые вызовы поддерживают доказанные scalar defaults. Строка, начинающаяся
  с `%`, остаётся строкой, а не ссылкой на SSA-регистр. Составные/вычисляемые
  defaults нельзя подменять вновь созданными объектами в месте вызова.
- `phi_lowering.py` переносит SSA-слияния на входящие рёбра CFG. Только выбранное
  значение читается существующей командой копирования VM; обработчик `phi` не
  вызывается. Условные рёбра разделяются, в безусловный переход копии вставляются
  непосредственно. Параллельные присваивания сохраняют старые значения; только
  циклы копирования требуют временного слота. Границы памяти берутся из уже
  преобразованного bytecode, дополнительного поля/стека в C VM нет.
- `and`, `or`, условное выражение и цепочка сравнений сохраняют сам Python-объект
  результата. Ложное перегруженное сравнение не подменяется константой `False`,
  последний результат не подвергается дополнительному `__bool__`.
- Арифметические примитивы в `Source/C/python_vm/pyz80_target_object_runtime.c`
  записаны как явные действия над 32-битными значениями с комментариями
  `LD`, `ADD`, `SUB`, `NEG`, `SHL`, `SHR`, `CP`, `ST`. Это псевдооперации,
  не обещание одной инструкции Z80 или известного числа тактов.
- `//` округляет вниз, `%` сохраняет знак делителя. Знаковое переполнение и
  недопустимые сдвиги не исполняются как неопределённые операции C.
  Сохраняется различие результатов `bool` и `int`.
- `/` не подменяется целочисленным делением. Float, bigint и исключительные
  случаи передаются внешнему обработчику; без него runtime отказывает.
  Полной реализации числовой модели Python этот быстрый i32-путь не заменяет.
- Генератор C-таблиц связывает имена полей dataclass с теми же символами, что
  используют обычные обращения к атрибутам. `PyZ80Target_StoreFields` исполняет
  этот порядок для plain-object узлов; preflight проверяет схему, цепочки полей
  и ёмкость до записи. Существующий core затем вызывает `__post_init__`.
  `PyZ80Generated_Bind` подключает сгенерированные таблицы к контексту после
  `PyZ80Target_Init`. Это не реализация пользовательских дескрипторов или
  `__setattr__`; связывание таких классов остаётся отдельной обязанностью.
- Ссылки на внутренние функции представлены узлами runtime с точным ID PZVT;
  связанный метод хранит настоящий `self`. Генератор переводит наборы кандидатов
  в числовые таблицы и объединяет одинаковые таблицы проверки/извлечения receiver.
  `require-callable`, выбор конечного кандидата и извлечение `self` исполняются
  общим C-кодом. Неверный ID, индекс, поколение ссылки, недопустимый receiver
  и нехватка узлов приводят к отказу. Это не заменяет поиск методов через
  дескрипторы или полную реализацию динамических вызовов.
- `closure_lowering.py` связывает вложенное определение с функцией по точному
  владельцу, модулю, ссылке определения и хешу AST. Для синхронных определений
  без defaults преобразует операнды в globals и ссылки на ячейки. Тела не
  исполняются при создании; defaults не отбрасываются и остаются неподдержанным
  путём. Аннотации сохраняются в описании адаптера; runtime-интроспекция
  атрибутов функций ещё не реализована.
- `pyz80_target_scope_runtime.c` хранит захваченные переменные в общих ячейках:
  дальнейшее присваивание родителя обновляет ячейку, а не заменяет её снимком.
  Замыкание сохраняет ячейки и идентичность globals после возврата родителя.
  `PyZ80Target_AttachScopes` подключается после `PyZ80VM_Init` с отдельной
  caller-owned таблицей ссылок на замыкания по глубине стека и таблицей
  отображений globals по ID функции. Модули должен инициализировать загрузчик;
  объединять все globals в один словарь нельзя.
  `PyZ80VM_StartClosure` запускает возвращённое замыкание с аргументами в
  доказанном ABI-порядке. Конечный lexical-dispatch также использует сохранённое
  окружение, а не ищет единственный живой кадр родителя, когда подключены hooks.
  Ячейки пока создаются только для уже связанных имён; unbound/nonlocal/delete,
  lambda и генераторы требуют
  продолжения реализации. Дополнительное хранилище не входит в VM_ArenaBytes;
  его время жизни и полный машинный стек ещё не доказаны.
- Обход полей ограничен числом выделенных записей: повреждённая циклическая
  цепочка при поиске отсутствующего поля не может навсегда занять runtime.

## Проверка

```powershell
$env:PYTHONPATH = 'Source/Tools'
python -m unittest test_pyz80_call_lowering_regressions test_pyz80_backend_rebuild test_pyz80_target_arithmetic test_pyz80_target_object_runtime -v
python -m unittest test_pyz80_phi_lowering test_pyz80_dataclass_runtime test_pyz80_generated_adapter_bundle -v
python -m unittest test_pyz80_callable_runtime -v
python -m unittest test_pyz80_scope_runtime -v
```

Тест арифметики компилирует и исполняет C на host CPU и сравнивает 10 492
случая с Python: границы i32, оба знака, bool, сдвиги, деление и
детерминированные случайные пары. Дополнительно проверяются три передачи
управления внешнему обработчику. Отдельный тест компилирует runtime закреплённым
SDCC для Z80 с автоматическим стеком и проверяет отсутствие статических
рабочих данных. Это не проверка скорости Z80 и не покадровая проверка игры.

Сквозной тест берёт AST выражений, выполняет сгенерированный PZVT в настоящем C
VM вместе с generic object runtime и сравнивает 2592 набора входов с Python.
Отдельно проверяются обмен в цикле, идентичность объектов, число проверок
истинности и 41 вызов инициализатора с `__post_init__`. Сгенерированные C-таблицы
компилируются TCC и SDCC, их подключение проверяется исполнением host-C.
Тест связанных callback передаёт два метода в C VM без внешнего обработчика:
проверяются выбранная функция, keyword binding, результат и запись в настоящий
`self`, в том числе для одной функции на двух разных объектах.
Тест замыканий начинает с AST, исполняет C VM после возврата родителя и сравнивает
результаты с Python. Проверяются позднее присваивание, раздельные окружения,
повторный захват той же ячейки через возвращённое замыкание,
повреждённая ячейка без fallback, сохранение неподдержанных defaults и
компиляция scope-runtime для Z80 без статических рабочих данных.

## Следующая граница готовности

Нужны исполнение оставшихся Python-операций/вызовов, сохранение и возобновление
генераторов, аппаратные обработчики, итоговая линковка, доказанный полный
стек и измерение времени кадра. Только затем новый SPG и сравнение состояний
с одинаковыми входами и номером кадра. Отчёт о покрытии не снимает эти условия.
